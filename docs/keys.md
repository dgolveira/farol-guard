# SSH keys and security model

farol-guard can install, rotate and remove keys in `authorized_keys` across the
fleet. Because the source code is public, nothing in it may help an attacker:
the security of every installation rests only on secrets generated at runtime
on that installation.

## The app key

`farol-app` is a dedicated key for farol-guard itself, separate from your
personal keys, so scheduled checks do not depend on a human key and access can
be revoked independently.

| Layer | What it protects against |
| --- | --- |
| Ed25519 key generated from the kernel CSPRNG (`crypto/rand`, `getrandom(2)`), 256 bits, no seed, timestamp or counter | guessing or reproducing a key from the source code |
| One key per installation; no default, embedded or shared keys exist | someone downloading farol-guard already holding a valid key |
| Private key encrypted with a random 256-bit passphrase kept in the system keyring (Secret Service / GNOME Keyring) | theft of the key file, leaked backups, copied disks |
| `restrict` option on the servers (no forwarding, no PTY, no `~/.ssh/rc`) | using the key as a pivot or tunnel |
| Optional `from="<address>"` option | using the key from anywhere else, even if key and passphrase leak |
| Host key verification against `known_hosts` | a machine impersonating a server |
| Rotation with verification and rollback, timestamped `authorized_keys` backups | long-lived credentials and lockouts |

A test in the repository fails the build if `math/rand` is imported anywhere, so
predictable randomness cannot creep into key or secret generation.

### Passphrase handling

You never type or see the app key passphrase. farol-guard creates it, stores it
in the keyring under the service `farol-guard`, and unlocks the key whenever it
needs it while your desktop session is open. Where no keyring exists (Docker,
headless servers) the passphrase comes from `FAROL_GUARD_APP_PASSPHRASE` or a
systemd credential named `farol-app-passphrase`; see [hosting](hosting.md).

If the keyring is lost the key file can no longer be opened. That is by design:
use your personal key to run "Replace app key" and a new app key is issued.

An app key created before this protection existed can be encrypted in place
with "Protect with the keyring" (or `farol keys app-protect`). The fingerprint
does not change, so nothing changes on the servers.

### Signature

App keys carry a comment such as
`farol-guard:app:<installation-id>@<host> <date>`. Ownership is decided by the
fingerprint (only this installation holds the private key); the comment lets
reports recognize keys installed by **other** farol-guard installations and
flag them.

## Operations

All operations accept a dry run, back up `authorized_keys` before writing
(`authorized_keys.farol-<timestamp>`) and keep the original SSH session open so a
failed verification can be rolled back.

| Operation | What happens |
| --- | --- |
| Deploy | Appends the key (or updates the options of an existing line), then logs in with the new key to verify it. Rolls back on failure. |
| Rotate | Deploys the new key, verifies it, then removes the old key only on hosts where the new one works, and verifies again. |
| Remove | Removes a fingerprint and checks that farol-guard can still log in. Refuses to remove the key farol-guard itself uses unless a new key is being rotated in. |
| Replace app key | Rotates `farol-app` on every host where the latest report found it. The old key is retired locally only if every host succeeds; otherwise run it again to resume. |

CLI equivalents:

```bash
farol keys list
farol keys fleet                         # keys found in the latest report
farol keys new grp-production --passphrase
farol keys deploy grp-production -g production --dry-run
farol keys rotate grp-production -g production --remove-current
farol keys remove SHA256:... -H web01
farol keys app-init -g production --from 203.0.113.10
farol keys app-rotate
farol keys app-protect
farol keys pub farol-app --from 203.0.113.10
```

Key operations never default to the whole fleet: a group or host must always
be selected.

## Files

| Path | Content |
| --- | --- |
| `~/.config/farol-guard/keys/` | keys generated by farol-guard (mode 600) |
| `~/.config/farol-guard/instance-id` | installation id used in key comments |
| `~/.config/farol-guard/inventory.yaml` | inventory, known keys, thresholds |
| `~/.local/share/farol-guard/reports/` | report history (last 200) |
| `~/.cache/farol-guard/osv/` | CVE lookup cache |
| `~/.ssh/known_hosts` | trusted host keys (shared with OpenSSH) |
